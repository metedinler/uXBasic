On Mete's machine PowerShell runs with the tr-TR culture and a guard on the removal cmdlet:

- `"init".ToUpper()` gives `İNİT` (dotted capital İ, U+0130). Code I generated (uXBasic wrapper names like `İnitSubsystem`) failed the lexer with `LEX_UNKNOWN_CHAR` (26 diagnostics). **Use `.ToUpperInvariant()` / `.ToLowerInvariant()`** for any generated identifier or symbol; also for `-replace`/`-match` case tricks.
- `$raw -split "`r?`n", -1` did NOT return the lines (later `$lines[$i]` was null) and my rewrite of 4 source files ran on that broken array before I noticed (content survived only by luck). **Never rewrite a source file from a `-split` result**; use the Edit tool (exact strings), or `[System.IO.File]::ReadAllText` + `.Replace()` on the raw text and keep the file's own line ending (`if ($raw.Contains("`r`n"))`).
- A script text that contains the removal cmdlet (Remove-Item ... -Recurse) is rejected as a whole ("blocked ... protected"), even inside a here-string that only WRITES a script file. Use `[System.IO.Directory]::Delete($path, $true)` / `[System.IO.File]::Delete()` there. (See [[powershell-erase-alias-blocked]].)
- Lines printed by `PRINT "a=" ; f()` from a uXBasic program get glued to the runtime's `INFO:`/`FFI CALL(DLL)` log lines when a call logs in between; build one string (`r = "a=" + STR(x)`) and PRINT it once, or filter lines with `Where-Object`.

**Why:** each of these cost a build/debug cycle (a whole wrapper file had to be regenerated by post-fix).
**How to apply:** default to the invariant methods and .NET file APIs for anything generated or bulk-rewritten in PowerShell here.
