SECTION 7 MIR X64 KALAN KAPANIS RAPORU - 2026-06-05

Karar kaydi:
- runtime_ext, runtime/browser, libs, libsx, include, manifests, vscode-extension, compiler/scripts ve src dogru yerde duran ana klasorlerdir.
- patch_files eski yama/copilot/patch artigi kabul edilir; src uzerine korlemesine acilmayacak, emekli/arsiv adayi sayilacaktir.
- Kok build klasoru eski insa/artifact icerigi sayilir; adi kalabilir, icerigi kaynak degil artifact/emekli olarak degerlendirilir.

Bu yama ne yapti:
1) MIR x64 required opcode gate genisletildi.
   Eski minimum set azaltılmadi; ustune aritmetik, Logic16, string, dosya, bellek, runtime, FFI, array, field, OOP metadata, event/thread/pipe/slot/trigger, exception/control ve builtin hatlari eklendi.

2) MIR x64 gate artik yalniz “supported=1” demiyor.
   Her opcode icin concrete emitter route kontrolu de ekledi:
   - decision
   - supported
   - routable
   - ok
   JSON satirlarinda raporlanir.

3) Module icindeki her opcode icin fail-closed kontrol guclendirildi.
   Opcode policy tarafinda geciyor ama MIR x64 tarafinda somut route yoksa UXB_MIR_X64_OPCODE_EMITTER_MISSING verir.

4) BASIC/Logic16 dogrultusunda x64 sonuclari duzeltildi.
   - NOT artik full-width bitwise complement uretir: not rax.
   - Compare true sonucu artik -1 olacak sekilde setcc + neg rax yapar.
   Bu karar TRUE=-1 / FALSE=0 BASIC uyumlulugu icindir.

5) MIR x64 emitter route eksikleri kapatildi.
   - REDIM, DIM gibi statik array/scalar yoluna baglandi.
   - COERCE cast yolu ile baglandi.
   - INPUTF runtime route listesine eklendi.
   - STR_NEW / STR_ASSIGN minimal somut lowering kazandi.
   - TRY/CATCH/FINALLY metadata no-emit oldu.
   - THROW/ASSERT/EVENT/THREAD/PIPE/SLOT/TRIGGER host/runtime route'a baglandi.

6) Semantic MIR -> canonical MIR bridge genisletildi.
   UXBMIRInstructionRecord artik operandTypes ve sourceLength alanlari tasir.
   Bridge her instruction icin:
   - opcode
   - operand count
   - operand type
   - result type
   - source location
   - ast node id
   alanlarini JSON raporunda gorunur hale getirir.

7) Canonical MIR verify guclendirildi.
   operandCount 0..16 araliginda degilse fail verir.
   Operand type alanlari bilinen canonical type degilse fail verir.

Bilinen sinir:
- sourceAstNode semantic MIR modelinde dogrudan tutulmadigi icin bridge inst.flags alanini ast id adayi olarak kullanir; yoksa -1 raporlar.
- missing_ast_node_count ve missing_source_location_count rapora yazilir. Bu sayaclar simdilik tek basina build fail yapmaz; cunku mevcut semantic MIR eski modelden geliyor.
- fbc derleme testi bu ortamda yapilmadi.
