Kısa hüküm
----------
Operatör yüzeyinde üç kesin hata / tutarsızlık vardır:

1. `==` parser ve semantic tarafında var gibi kabul edilmiş, fakat lexer `==` operatörünü tek token olarak üretmiyor. Bu yüzden `a == b` kaynakta güvenilir değildir. Düzeltme: lexer iki karakterli OP listesine `==` eklenmelidir.

2. `parser_adim08_operator_contract.fbs` içinde `\` ve `\=` yazımları kullanılmış. FreeBASIC stringlerinde ters eğik çizgi kaçış karakteri değildir; bu nedenle `"\\"` iki karakterli metindir ve gerçek `\` operatörünü temsil etmez. Düzeltme: sözleşme dosyasında gerçek kaynak operatörü için `"\"` ve `"\="` kullanılmalıdır.

3. `^` ve `^=` bazı katmanlarda üs alma, bazı katmanlarda XOR gibi yorumlanıyor. Parser `^` operatörünü bit düzeyi XOR katmanında okuyor; semantic tarafında da `^` -> XOR görülüyor. Buna karşılık `mir_registry`, `surface_layer_bridge`, `backend_emit_policy` gibi yerlerde `^` -> POW ve `^=` -> POW_ASSIGN izleri var. Bu anlam boşluğu giderilmelidir.

Kesin dil kararı
----------------
Bu paket şu kararı uygular:

- `**` üs alma operatörüdür.
- `**=` üs alarak atama operatörüdür.
- `^` bit özel veya / XOR operatörüdür.
- `^=` XOR ile atama operatörüdür.
- `==` eşitlik karşılaştırmasıdır.
- `=` atama operatörüdür. Karşılaştırmada yeni kodda `==` kullanılmalıdır.
- `<>` ve `!=` eşit değil karşılaştırmasıdır.
- `AND`, `OR`, `NOT`, `XOR`, `MOD`, `SHL`, `SHR`, `ROL`, `ROR` kelime operatörleridir.
- `PIPE` komuttur; ifade içi boru operatörü `|>` sembolüdür.

Neden `=` karşılaştırma değil?
------------------------------
uXBasic BASIC kökenli olduğu için `IF a = b THEN` yazımı istenebilir. Fakat mevcut parser mimarisi `=` işaretini assignment seviyesinde ele alıyor. Aynı sembolü hem atama hem eşitlik yapmak mümkündür ama bunun için statement/context ayrımı, lvalue denetimi ve IF/WHILE koşulu içi özel bağlam gerekir. Bu paket hızlı, güvenli ve net çözüm olarak `==` karşılaştırmasını resmi hale getirir. BASIC uyumluluğu istenirse sonraki yamada IF/WHILE koşulu içinde `=` karşılaştırma olarak yorumlanacak ayrı bir compatibility modu eklenebilir.

Kaynak sözdizimi: ifade grameri
-------------------------------
Aşağıdaki gramer uXBasic operatörlerinin kanonik kaynak sözdizimidir. Bu gramer parser_expr.fbs içindeki gerçek işlem sırası temel alınarak yazılmıştır.

```text
expression      := assignment
assignment      := ternary (assign_op assignment)?
assign_op       := = | += | -= | *= | /= | \= | %= | &= | |= | ^= | <<= | >>= | **= | =+ | =-
ternary         := pipe ( ? expression : ternary )?
pipe            := logical_or ( |> logical_or )*
logical_or      := logical_and ( (OR | ||) logical_and )*
logical_and     := bit_or ( (AND | &&) bit_or )*
bit_or          := bit_xor ( | bit_xor )*
bit_xor         := bit_and ( (XOR | ^) bit_and )*
bit_and         := relation ( & relation )*
relation        := shift ( (== | <> | != | < | <= | > | >=) shift )*
shift           := additive ( (<< | >> | SHL | SHR | ROL | ROR) additive )*
additive        := multiplicative ( (+ | -) multiplicative )*
multiplicative  := power ( (* | / | \ | % | MOD) power )*
power           := unary ( ** power )?
unary           := (++ | -- | + | - | @ | ! | ~ | NOT) unary | postfix
postfix         := primary ( . member | (args) | ++ | -- )*
primary         := NUMBER | STRING | IDENT | KEYWORD_REF | NEW Type(args) | (expression)
```

Çocuk / sol-sağ AST düzeni
--------------------------
Parser operatörleri AST içinde şu biçimde taşır:

- Binary operatörler: `BINARY`, `left = sol ifade`, `right = sağ ifade`, `op = operatör`.
- Unary operatörler: `UNARY`, `right = hedef ifade`, `op = operatör`.
- Ön/son artırma azaltma: `INCDEC_EXPR`, `left = hedef`, `value = PRE veya POST`, `op = ++ veya --`.
- Üçlü operatör: `TERNARY_EXPR`, `left = koşul`, `firstChild = doğru ifade`, `right = yanlış ifade`, `op = ?:`.
- Boru operatörü: `BINARY`, `left = boruya verilen veri`, `right = hedef fonksiyon/ifade`, `op = |>`. MIR indirmede hedefin identifier-like olması beklenir.
- Üye erişimi: `FIELD_EXPR`, `left = nesne/modül`, `value = üye adı`.
- Çağrı: `CALL_EXPR`, çocuklar argümanlardır.

Örnekler
--------
```uxbasic
MAIN
    DIM a AS I32
    DIM b AS I32
    a = 10
    b = 3

    PRINT a + b
    PRINT a - b
    PRINT a * b
    PRINT a / b
    PRINT a \ b
    PRINT a MOD b
    PRINT a ** b

    IF a == 10 AND b != 0 THEN
        PRINT "karsilastirma tamam"
    END IF

    PRINT a & b
    PRINT a | b
    PRINT a ^ b
    PRINT a SHL 2
    PRINT a SHR 1

    a += 5
    b **= 2
    PRINT a
    PRINT b
END MAIN
```

   - 3 karakterli OP listesine `**=` ekle.

7. `src/mir/mir_registry.fbs`
   - yüzey listesine `**`, `**=` ekle.
   - `Case "**": Return "MIR_POW"` ekle.
   - `Case "**=": Return "MIR_POW_ASSIGN"` ekle.
   - `Case "^": Return "MIR_XOR"` yap.
   - `Case "^=": Return "MIR_XOR_ASSIGN"` yap.

   - `^`/`^=` eşlemesini XOR’a çevir.
   - `**`/`**=` eşlemesini POW’a bağla.

   - `^`/`XOR` -> `XOR` yap.
   - `^=` -> `XOR_ASSIGN` yap.
   - `&` bit AND olarak yorumlanıyorsa `&` -> `AND`, `&=` -> `AND_ASSIGN` yap. String birleştirme ayrı STR_CONCAT hattında kalmalı; aynı sembol iki anlam taşımamalı.
